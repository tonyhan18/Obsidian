# AI 활용 방안 — 컨텍스트 비용을 아끼는 전략

## 핵심 문제

AI에게 작업을 맡길 때마다 **컨텍스트 비용이 누적**된다. 작업이 진행 중일 때 계속 "끝났어?"라고 물어볼 때마다:

1. 현재까지의 대화 맥락 전체가 다시 전송됨
2. 토큰 사용량이 계속 증가함
3. 비용이 불필요하게 늘어남

## 전략 1: 끝내고 기다려라고 말해라

> **"끝내고 기다려. 끝나면 하네스가 다시 불러."**

AI에게 작업을 맡긴 후, 진행 상황을 묻지 않는다. 작업이 완료되면 **Hermes가 자동으로 알림을 보내기 때문에** 굳이 물어볼 필요가 없다.

### 작동 원리

```
사용자: "이 작업 끝내줘"
    ↓
AI: 백그라운드에서 작업 시작
    ↓
사용자: 기다림 (물어보지 않음) ← 핵심
    ↓
작업 완료 → Hermes 자동 알림
    ↓
사용자: 결과 확인
```

### 비용 비교

| 방식 | 컨텍스트 전송 | 비용 |
|------|-------------|------|
| 매번 물어보기 | 대화 맥락 × N번 | 높음 |
| 기다렸다가 알림 받기 | 완료 시 1회 | 낮음 |

## 전략 2: 배치 작업으로 묶어서 요청

여러 작업을 개별적으로 요청하지 말고 **한 번에 묶어서** 요청.

- ❌ "요약해줘" → "번역해줘" → "정리해줘" (컨텍스트 3회)
- ✅ "요약하고 번역하고 정리해줘" (컨텍스트 1회)

## 전략 3: 새 세션에서 새 작업

Hermes는 대화가 길어지면 자동으로 컨텍스트를 압축하지만, 압축에도 비용이 든다.

1. 새 작업은 **새 세션**에서 시작 (`/new`)
2. 이전 결과는 **위키에 저장** → 다음 세션에서는 링크만 참조
3. 컨텍스트가 아닌 **파일 시스템의 지식**을 활용

## 전략 4: 스크립트 기반 자동화

반복 작업은 AI에게 매번 맡기지 말고 **스크립트로 자동화**.

- ❌ 매번 "뉴스 수집해줘" → 매번 컨텍스트 비용
- ✅ cron job으로 1시간마다 자동 수집 → 컨텍스트 비용 **0**

## 전략 5: 캐시 우선 실행 (Cache-Write First)

여러 에이전트가 동시에 돌아갈 때, **캐시 라이트를 먼저 실행**한 후 나머지를 실행한다.

### 문제

여러 에이전트가 동시에 같은 컨텍스트를 참조하면:
1. 각 에이전트가 독립적으로 전체 컨텍스트를 로드 → 중복 비용
2. 캐시가 채워지기 전에 실행되면 캐시 효과 없음

### 해결: Cache-Write First 패턴

```
1단계: 첫 에이전트 실행 (Cache-Write)
   - 전체 컨텍스트 로드 → 캐시에 저장
   - 이 시점에서 캐시가 "워밍업"됨

2단계: 나머지 에이전트 실행 (Cache-Read)
   - 캐시에서 컨텍스트 로드 → 비용 절감
   - 캐시 히트로 토큰 비용 대폭 절감
```

### 비용 비교

| 방식 | 컨텍스트 로드 | 비용 |
|------|-------------|------|
| 동시 실행 (캐시 없음) | 전체 × N 에이전트 | 최대 |
| 캐시 라이트 먼저 → 나머지 실행 | 전체 1회 + 캐시 hit × (N-1) | 최소 |

### 실전 적용

- **delegate_task**로 여러 서브에이전트를 실행할 때, 첫 에이전트가 완료된 후 나머지를 실행
- **cron job**에서 첫 실행이 캐시를 채우고, 이후 실행은 캐시를 활용
- Hermes의 `context_from` 기능으로 이전 작업 결과를 캐시처럼 활용

## 요약

| 전략 | 효과 |
|------|------|
| 끝내고 기다려라고 말하기 | 불필요한 폴링 비용 제거 |
| 배치 작업 | 컨텍스트 재사용으로 비용 절감 |
| 새 세션에서 새 작업 | 컨텍스트 압축 비용 회피 |
| 스크립트 자동화 | 반복 작업 컨텍스트 비용 0 |
| **캐시 우선 실행** | **여러 에이전트 동시 실행 시 캐시 히트로 비용 절감** |

> **핵심: AI에게 맡긴 작업은 끝날 때까지 기다려라. Hermes가 알려준다.**
